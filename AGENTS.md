# Repository maintenance

Read `docs/maintenance-record.md` and `.github/maintenance.json` before changing repository organisation or documentation.
The organisation baseline was established on 2026-10-06. Preserve it and update only material affected by new code or a new user request; do not repeat the initial reorganisation.
Use professional English for authored documentation. Keep claims grounded in the source and distinguish implemented behaviour, known limitations, and proposed improvements.
Preserve original learning exercises, filenames, IDE project references, and visibility unless the user explicitly requests a change. Never copy private repository contents into public repositories without specific authorisation.
Keep compiler output, temporary files, and machine-specific verification logs out of commits. Before publishing, inspect the diff and verify affected links, build commands, and examples.
Update the maintenance record and content hashes when making intentional changes. Do not overwrite concurrent user edits or force-push history.
